# 词库数据与通用学习器（日语版）

## 单集词库数据

每集先整理为一个 deck 对象，再合并到学习器的 `decks` 列表。日语词条在 `cards` 中额外使用 `reading` / `romaji` / `pos` / `grammar` 四个可选字段，强化日语专属学习信息（读音、罗马字、品词、语法备注）。

```json
{
  "title": "日语剧集 实例句 · JLPT N3–N2",
  "deck_id": "demo:jpn:N3N2",
  "language": "日本語",
  "exam_target": "JLPT",
  "level_target": "N3–N2",
  "selection_basis": "日语原字幕；按 JLPT N3–N2 高频范围筛选",
  "difficulty_feedback": "",
  "sources": ["真实来源 URL 或用户提供的字幕文件名称"],
  "note": "可选说明，例如材料不足，仅提取 32 条。",
  "cards": [
    {
      "term": "修理",
      "reading": "しゅうり",
      "romaji": "shūri",
      "pos": "名詞",
      "grammar": "~する 動詞；「修理する」",
      "answers": ["修理", "しゅうり"],
      "meaning": "修理；维修",
      "sentence": "このパソコンは修理が必要です。",
      "translation": "这台电脑需要修理。",
      "targets": ["修理"]
    }
  ]
}
```

`title` 和 `deck_id` 必填；`language`、`exam_target`、`level_target`、`selection_basis`、`difficulty_feedback` 可选，缺省使用空字符串；`sources` 必须是字符串数组；`cards` 接受 1–500 条。每张卡的 `term`、`meaning`、`reading`、`sentence`、`translation` 都是非空纯文本，不放 HTML 标记。`answers` 和 `targets` 可省略，必须是非空字符串数组；省略时分别默认为 `[term]` 和 `[term]`。只把语义正确、拼写确实可接受的形式放入 `answers`（日文建议同时收「汉字词」和「假名读音」，如 `["修理","しゅうり"]`）。

### 日语专属可选字段

- `reading`：单词的假名读音（ひらがな）。最重要，建议在词卡与总览中都显示，帮助记住发音与汉字对应。无汉字的纯假名词也照填（如 `わかる`）。
- `romaji`：罗马字读音（如 `shūri`），面向中文母语者的发音辅助，可空；长音用 `ā/ī/ū/ē/ō` 标记。
- `pos`：品詞（词性），如 `名詞` / `動詞(他)` / `動詞(自)` / `い形容詞` / `な形容詞` / `副詞` / `助詞` / `接続詞` / `感動詞` / `慣用句`。学习器会在语法备注前显示品詞。
- `grammar`：一句语法/用法备注，例如 `自動詞／他動詞`、`て形「預けて」`、`敬語：〜ていらっしゃる`、`接尾辞「〜っぽい」表倾向`、`「〜わけだ」表缘由`。自由文本，可空。

`deck_id` 对一个剧集必须稳定，例如 `dark:S01E01:jp`。更新同一集时沿用原 ID，不要因标题、字幕来源或词条顺序变化而另建重复 deck。同 ID 导入表示更新该集：元信息和卡片列表采用新版本；同 ID 词条保留已有进度，新加入或身份变化的词条从未学习开始。其他剧集 deck 与进度不变。

不要手工填写卡片 `id` 或 `target_spans`。生成/合并工具根据词头与规范化原句生成稳定 ID，并计算目标片段位置；HTML 页面用这些位置显示高亮和挖空。原句中实际形式与词头不同时，`targets` 必填，例如 `term` 为 `預ける`、原句为 `荷物をロッカーに預けた。` 时可设为 `["預けた"]`。目标片段必须按原样出现在原句中，不能改原句迁就词头；目标片段不能重叠。

## 内嵌词库集合

通用学习器把完整词库集合嵌入一个 application/json 脚本节点。模板只使用此占位约定：

```html
<script type="application/json" id="vocab-library">__VOCAB_LIBRARY__</script>
```

生成后的占位符必须替换为一个有效 JSON 对象，根形状如下：

```json
{
  "schema_version": 1,
  "decks": [
    {
      "title": "日语剧集 实例句 · JLPT N3–N2",
      "deck_id": "demo:jpn:N3N2",
      "cards": [],
      "sources": [],
      "note": ""
    }
  ]
}
```

集合内每个 deck 使用上面的单集词库结构。首次创建学习器时，`decks` 至少包含本次首集词库；不可生成空库。后续只向集合新增或替换 deck，然后把完整集合安全写回固定母版 HTML。对 JSON 做安全序列化，避免词条中的 `</script>`、`<`、`>`、`&`、U+2028 或 U+2029 破坏内嵌数据；页面以 `textContent` 等安全方式渲染用户字幕文本。页面中的词库说明应显示学习语言和考试/等级范围，方便用户判断这批词按什么标准筛出。

## 词库、进度和偏好边界

`nihongo-vok.html` 保存完整 `vocab-library`，复制 HTML 文件即可备份全部词库。练习进度以 `deck_id` 和词条 `id` 为键分开保存，翻卡自评/输入回忆的选择是通用学习器的浏览器偏好，对全部 deck 生效。页面进度备份保存浏览器学习状态，不包含词库正文；HTML 备份也不包含浏览器进度或偏好。完整迁移时同时保留 HTML 文件和页面导出的进度备份。更换浏览器、设备或移动文件后，本地存储可能无法自动跟随。

## 文件处理规则

- 固定母版路径为 `~/Documents/nihongo-vok.html`。首次创建时从技能模板生成学习器并放入首集词库；后续新增/更新一集时，必须读取现有文件、保留其他 deck 并合并回同一文件。
- 如果既有母版不存在、不可读、损坏，或当前 Agent 看不到，不要创建空库或只包含新集的替代文件。向用户索要现有 HTML 的路径或文件后再继续。
- 普通使用最终交付更新后的 HTML 并说明加入的剧集及词条数。单集 JSON 是中间数据，不需单独交付；除非用户明确要求数据包。
- 不分发整集字幕，只把精选且真实来源可核实的学习例句放入 cards。
